# ТехноПринт — план переделки UBC (2026)

## 1. Видение
Одна веб-система = текущая **CRM** (заказы, деньги, долги, ЗП, отчёты, Telegram-бот)
+ 2 модуля из **UBC**: **Заправки** и **Выписка документов**.
Доступна с телефона, self-hosted (без зарубежных CDN), всё в одном.

## 2. Что берём / что убираем
**Берём:** Заправки картриджей (карты + история + штрихкоды + нормы/спеки как справочник);
Выписка (счета/акты + печать PDF + этикетки).
**Убираем:** склад с учётом тонера «до грамма» (он блокирует заправку «нет тонера») →
тонер делаем СПРАВОЧНО, заправку не блокируем никогда; сервис/ремонт (маленький — позже);
мультифилиал/тендеры/согласование документов (коммерческое); лицензирование/ключи (tPar #36).
**Остаётся в CRM (не дублируем):** ЗП/рейтинг, отчёты/аналитика, SMS/Email, скидки/лимиты.

## 3. Архитектура
- Backend: расширяем FastAPI + Postgres (новые таблицы + роутеры).
- Frontend: тот же Alpine + Tailwind веб, новые экраны «Заправки» и «Выписка», vendor локально.
- Печать: серверный HTML→PDF (WeasyPrint / headless) → счёт, акт, этикетка/штрихкод.

## 4. Модель данных (новые таблицы) ← маппинг из UBC Access
- `cartridge_models` ← CartModels + CartManuf (производитель, модель, тип, норма тонера справочно, цена-подсказка)
- `cartridges` (карты) ← CartCards (штрихкод, клиент→clients, модель, постоянный, остаток, заметка)
- `cartridge_refills` (история) ← CartCardsTable (карта, дата, заправщик→users, дефект, заметка, ссылка на заказ/документ)
- `documents` ← Account/AccountAct (тип счёт/акт, номер, дата, клиент, сумма, статус)
- `document_items` ← AccountT/AccountActT (наименование работа/товар, ед., кол-во, цена, сумма)
- Переиспользуем существующие: clients, services, users (заправщики), orders.

## 5. Миграция данных
mdbtools экспорт (Server.uco) → трансформация Python → загрузка в Postgres.
Клиентов смёржить с текущими (резолвер по имени), заправщиков → users,
карты (4965) + историю заправок (18819) + модели/производители перенести.

## 6. Ключевой фикс (боль)
Тонер — информационно (показываем расход/остаток), но заправку НЕ блокируем. Учёт до грамма убираем.

## 7. Фазы
- **P1.** Миграция данных (клиенты, модели, карты, история) → просмотр заправок в вебе.
- **P2.** Ввод заправки (заправщик/дата/дефект), поиск по штрихкоду/клиенту, печать штрихкода.
- **P3.** Выписка: счёт/акт из заправок/заказов → строки → печать PDF, нумерация, история.
- **P4.** (опц.) товар из 1С как справочник позиций; сервис/ремонт — позже.
