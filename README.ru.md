# TechnoPrint CRM

**Система учёта, на которой работает реальный сервис по заправке картриджей и ремонту техники.**
Заменила VB6-программу 2004 года, 1С, которую держали ради счетов, и стопку таблиц Excel.
В работе с июня 2026 года — через неё проходит каждый картридж, ремонт, счёт, долг и зарплата.

Это не учебный проект. Требования пришли не из курса, а из мастерской: интернет отваливается,
зарубежные CDN заблокированы провайдером, бухгалтерии нужны печатные формы по российским правилам,
а владельцу — понимать, сколько наличных в кассе прямо сейчас.

## Контекст

Мастерская находится в Упорово — райцентр в Тюменской области, около 20 тысяч человек в округе.
Заправка картриджей, ремонт компьютеров и оргтехники, продажа расходников, печать. Основная выручка
идёт от бюджетных организаций — школы, детские сады, КЦСОН, администрации, — которые платят по
счетам на расчётный счёт, плюс частники за наличные.

До этой системы один и тот же заказ мог существовать в трёх местах и не сходиться ни с одним.

## Инженерная часть

То, что было действительно интересно сделать:

**Работа офлайн, потому что интернет и правда отваливается.** Фронтенд — PWA с service worker и
очередью записей в IndexedDB. Всё, что сделано без сети, встаёт в очередь, повторяется при
восстановлении связи и сверяется: записи, созданные офлайн, получают временный id, который
заменяется на серверный после синхронизации. Каждая отложенная запись несёт заголовок `X-Op-Id`, а
middleware на сервере отбрасывает повторы — плохая связь не может дважды списать деньги с клиента.

**Ни одного зарубежного CDN.** Российские провайдеры блокируют `cdn.tailwindcss.com`, `unpkg`,
`jsdelivr` и Google Fonts. Один `<script src="https://cdn…">` — и у пользователя пустой экран.
Все библиотеки лежат рядом и отдаются со своего домена. После каждого деплоя это проверяется
headless-браузером, которому эти хосты резолвятся в `0.0.0.0`.

**Одна запись на деньги.** Таблица `orders` — единственный источник правды: продажа за наличные это
оплаченный заказ, счёт — неоплаченный, то есть долг. Дашборд, список долгов и касса — производные от
неё. Нет параллельного учёта, который надо сводить, и нет способа получить разные цифры на двух
экранах.

**Дата работы против даты денег.** Зарплата и отчёты по разделам считают работу по месяцу, когда она
*сделана*; выручка — по месяцу, когда *выписан счёт*. Заправка, сделанная в июне и выставленная в
июле, даёт мастеру зарплату за июнь и выручку за июль — именно так это видят и мастер, и бухгалтер,
и одним полем с датой это не выразить.

**Миграции без Alembic.** При старте `_ensure_columns()` смотрит живую схему и добавляет
`ALTER TABLE … ADD COLUMN IF NOT EXISTS` всё, что описано в моделях, но чего нет в базе; новые
таблицы создаёт `create_all`. Только добавление — ничего не удаляется и не переписывается. Для
продукта с одним развёртыванием это заменило инструмент миграций, который всё равно никто не стал бы
поддерживать.

**Бэкапы со сторожем.** Ночной `pg_dump` на сервере, выгрузка на машину вне сервера дважды в день,
оттуда на NAS — три копии. На каждом шаге проверяется целостность архива и что свежая копия не
старше 26 часов, о сбое приходит сообщение в телеграм. Система появилась потому, что бизнес уже
терял данные один раз.

**Печатные формы.** Счета, акты, накладные и товарные чеки собираются на клиенте в HTML, готовый к
печати, — включая сумму прописью и блок банковских реквизитов в том виде, в каком его ожидает
бухгалтерия.

## Стек

**Бэкенд** — Python 3.12, FastAPI, SQLAlchemy 2 (async), PostgreSQL 16, JWT и bcrypt, WebSocket для
живых обновлений, телеграм-бот в том же процессе.
114 эндпоинтов в 18 роутерах, 32 таблицы.

**Фронтенд** — Alpine.js, Tailwind, Chart.js, JsBarcode, service worker, IndexedDB.
Без сборки: браузер загружает ровно те файлы, что лежат в репозитории.

**Инфраструктура** — Docker Compose, nginx, Let's Encrypt, небольшой VPS.

Около 5 900 строк Python и 5 500 строк фронтенда.

## Как запустить

```bash
cp .env.example .env                 # POSTGRES_PASSWORD для compose
cp backend/.env.example backend/.env # SECRET_KEY обязателен: openssl rand -hex 32
docker compose up -d --build
```

API поднимется на `127.0.0.1:8003` (`/docs` — OpenAPI, `/health` — проверка живости), фронтенд —
статические файлы, их отдаёт nginx, конфиг в `nginx.conf`.

Деплой на сервер — `./deploy.sh`, настройки он берёт из `deploy.env` (скопировать из
`deploy.env.example`). Скрипт синхронизирует код, создаёт файлы окружения, пересобирает контейнеры,
настраивает nginx и выпускает сертификат.

## Структура

```
backend/app/
  main.py          приложение FastAPI, middleware идемпотентности
  models.py        модели SQLAlchemy — 32 таблицы
  routers/         18 роутеров: заказы, клиенты, заправки, работы, товар,
                   документы, долги, зарплата, расходы, дашборд, журнал…
  telegram_bot.py  бот: сводки, долги, уведомления
  database.py      подключение, сессии, аддитивная авто-миграция
frontend/
  index.html       весь интерфейс (шаблоны Alpine)
  app.js           логика приложения
  offline.js       очередь записей, синхронизация, идемпотентность
  sw.js            service worker: стратегии кэширования
  vendor/          библиотеки рядом — никаких CDN
docker-compose.yml, nginx.conf, deploy.sh, backup_server.sh
```

## Чего здесь нет

Одноразовые скрипты, которые переносили историю из VB6-программы, 1С и таблиц, остались приватными —
в них таблицы сопоставления реальных клиентов. Дампы базы, кассовые книги и любые данные клиентов
тоже исключены, список в `.gitignore`.
